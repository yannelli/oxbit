Multiple Git accounts, commit signing, and collaboration off by default

1. Open Git Accounts and Commit Author. Add two GitHub accounts with Add GitHub Account, then tap Make Default on the second one. Check that the Default badge moves. Add a Gitea account with its server URL and token and check that it shows under its server.

2. If you used GitHub or Gitea in 0.3.3, check after updating that your account appears in the list as the default for its server and that fetch and push still work without entering the token again.

3. Open a repository that has two of your accounts on the same server. In This Repository, choose the account that is not the default. Fetch, pull, and push, and check that the server shows the chosen account. Remove that account and check that the repository goes back to the default account.

4. In Commit Signing, tap Create Signing Key, then Copy Public Key and add it to your GitHub or Gitea GPG keys. Turn on Sign commits, commit in a device folder, push, and check that the server shows the commit as verified. Import an existing armored key with its passphrase and check that the fingerprint matches. Remove the key and check that new commits are unsigned.

5. In Add-ons, check that Collaboration is off after updating and that Participants is gone from the status bar. Connect to a runtime, edit and save a file, and check that the save reaches the computer. Turn Collaboration on, open the same file on another paired session, and check that edits and saves appear on both.

Report crashes, accounts that disappear after updating, pushes that use the wrong account, unverified signed commits, or collaboration problems with reproduction steps, device model, iOS version, and screenshots.
