Language extensions for YAML, Dockerfile, shell, Zsh, and Python, and faster search

1. Open Extensions. Check that TypeScript / JavaScript, JSON, YAML, Dockerfile, Bash / sh, Zsh, and Python each appear as their own language server extension, and that each one turns off and on.

2. Open a GitHub workflow file (.github/workflows/*.yml). Check that completion suggests workflow keys and that a misspelled key such as "runs-onn" is underlined.

3. Open a Dockerfile, type an unknown instruction, and check that it is underlined. Check that hovering FROM shows its documentation.

4. Open a .sh file. Check that completion lists functions defined in the file and that an unclosed if block is underlined.

5. Open .zshrc or a .zsh file. Check that completion and the outline list its functions, and that valid Zsh syntax is not underlined.

6. Open a .py file with an undefined name and an unused import. Within about 10 seconds of the first open, check that each problem is underlined once.

7. In Extensions, tap Configure on YAML, add the file type **/*.yaml.tmpl, and open a file with that name. Check that it gets YAML completion. Remove the entry and check that it stops.

8. Turn off the Python extension and check that the underlines in the open .py file disappear. Turn it back on.

9. In a large folder, search the workspace for a word and open a file with Quick Open. Check that results appear quickly and that the matches are highlighted correctly.

10. In Settings > Privacy & Security > Local Network, turn off Oxbit. Open the Runtime page and check that it explains how to turn Local Network access back on. Turn it on and check that a runtime started with oxbit --lan appears.

Report crashes, memory warnings or the app closing while a Python file is open, missing or duplicated underlines, extensions that stay on after you turn them off, or slow search, with the file type, reproduction steps, device model, iOS version, and screenshots.
