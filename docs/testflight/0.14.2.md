Code fences

1. Open a Markdown file with a ```ts code fence, for example a README. Check that the code inside the fence is colored as TypeScript.

2. In the fence, write a line with a type error, such as const a: string = 1;. Check that the error is underlined and listed in Problems under the Markdown file.

3. In the fence, type the name of a variable followed by a dot. Check that completions appear and that picking one inserts it in the fence.

4. Tap or hover a variable in the fence and check that its type appears. Check that inlay hints, such as parameter names, appear inside the fence.

5. Open a TypeScript file with a doc comment that contains a ```ts fence. Check that the fence content is colored and checked.

6. In Settings, turn off Language Servers in Code Fences and check that the errors and hints in fences disappear. Turn off Highlight Code Fences and check that fence content is no longer colored. Turn both back on.

Report fences that stay plain, errors at the wrong position, completions that insert in the wrong place, and crashes, with reproduction steps, device model, iOS version, and screenshots.
