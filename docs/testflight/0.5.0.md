Runtime page, one-tap connect, and keep-alive

1. Open a device folder and tap the cloud button in the header. With no runtime saved yet, check that the Runtime page opens. It lists saved runtimes, runtimes on this network, SSH servers, keep-alive settings, and a pairing form.

2. On a Mac or Linux computer on the same Wi-Fi, install the CLI (npm install -g @oxbit/cli) and run oxbit --lan in a project folder. Allow Local Network access when iOS asks. Check that the runtime appears under "On this network" within a few seconds. Tap it, enter the pairing code the computer printed, and check that the workspace opens.

3. Close the workspace. On the start screen, tap Connect Runtime… and check that it connects to the same runtime without asking for the pairing code. In a device folder, tap the cloud button and check that it connects the same way and shows progress on the button.

4. Stop the runtime on the computer (oxbit --stop). Tap the cloud button and check that the Runtime page opens with the reason the connection failed.

5. On the Runtime page, set Keep Runtime Alive to 15 minutes. Start Oxbit on an SSH server, switch to another app for 5 minutes, and come back. Check that the workspace reconnects without starting the runtime again. Repeat with 75 seconds and a 3-minute wait, and check that the runtime was started again.

6. Turn off Reconnect Automatically, turn on Airplane Mode briefly, turn it off, and check that the workspace offers Reconnect instead of reconnecting by itself.

7. If you have a Linux arm64 server (for example a Raspberry Pi 5 or an AWS Graviton host), start Oxbit on it over SSH and check that the folder opens.

8. Open a Markdown file with links, a table, and inline code, and check that the preview renders them.

Report crashes, runtimes that do not appear on the network, pairing or reconnect failures, or a runtime that stops before its keep-alive time, with the computer or server OS, reproduction steps, device model, iOS version, and screenshots.
